## 1. 统一 agent 入口

塔罗和占星现在是主页上两个入口、两份各自的大提示词
（`tarot_system.md` / `astrology_system.md`，方法论大量重复，一直没去重）。

但这个分法在架构里已经名存实亡：开场幕对两者的判断逻辑本来就是同一套，
`<用户点开的入口>` 只是先验偏好，前置 Agent 判断另一条更合适可以改；
解读 Agent 的工具集里塔罗和星盘的工具都在，中途结合两者是常态。

要做的是把入口合成一个：用户只说自己想问什么，用塔罗还是星盘由占卜师定。
连带解决两份大提示词的重复。

## 3. 钩子

笔记本再产出第三样东西：**未完结的话题**，一句话 + 日期。
比如用户说「下周要跟她摊牌」，占卜完就走了——这就是一个钩子。
只落库，先不消费，它是下面那件事的原料。见 [笔记本](superpowers/specs/notebook.md)。

## 4. 关系环（依赖 3）

现在用户离开之后，这个产品就从他的生活里消失了。笔记本只让「他再来的时候」体验更好，
不解决「他想不起来再来」。

要做的是：占卜结束几天之后，占卜师**主动**接上那句没说完的话——
「上周你说要跟她摊牌，后来怎么样了？」

- **问候 Agent**：读钩子，写一句主动接话。
- **什么时候发**：距上次占卜超过 N 天，且有没消费过的钩子。
- **发在哪**（未定，二选一或都要）：主界面上占卜师主动搭话 / 旧会话窗口里延时接话。
- **绝对不放在新会话的开场里。** 用户开一场新的占卜是想问一件新的事，不是想被翻旧账。
  这条和「接场」的原则是同一条：老用户认得出来、叫得出昵称，但不主动提旧话题。
